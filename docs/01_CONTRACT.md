# 01 · The Data Contract (v1.1)

> **Read this before writing any code that reads or writes the cache.**
> This file is the single source of truth for every file the lanes exchange.
> If your code and this file disagree, this file wins. Change it only by team agreement (see §10).

---

## 1. Why this exists

Sightline has four lanes (A ML, B Geo, C Search, D Pipeline) and one website. They never call each other over the network. They meet in one folder, the **cache**. If every lane reads and writes exactly the shapes below, everyone can build in parallel against fake data from hour 1, and real data drops in later with no code changes.

Rules that follow from this:

1. **Only D's pipeline writes cache files.** Lanes A, B and C expose Python functions that return contract objects. D's pipeline calls them and writes the JSON. Nobody else writes into `cache/`.
2. **The website only reads the cache.** It never writes to it. Searcher answers live in browser state (see `05_FRONTEND_SHARED.md`).
3. **The contract is executable.** D implements every shape here as Pydantic v2 models in `sightline/contract.py`, and generates TypeScript types from them into `web/src/contract.ts`. Every cache write is validated against those models.

## 2. Conventions (apply everywhere)

| Thing | Convention |
|---|---|
| Coordinates | WGS84 decimal degrees. Objects use `{"lat": .., "lon": ..}`. **Polygons use GeoJSON order `[lon, lat]`.** |
| Distances | Metres, field names end in `_m`. |
| Angles | Degrees. **Heading = compass bearing the TOP of the image faces, clockwise from true north, 0–360.** |
| Pixels | Origin at the image's top-left, `u` to the right, `v` down. Boxes are `[x1, y1, x2, y2]` in pixels, integers, `x2 > x1`, `y2 > y1`. |
| Probabilities | Floats in [0, 1]. |
| Times | ISO 8601 UTC strings, e.g. `"2026-11-07T18:30:00Z"`. |
| IDs | Frames `f0001`…`f0500` (zero-padded to 4, numbered by flight order starting at 1). Detections `<frame_id>-d<NN>`, e.g. `f0042-d01`, numbered by descending confidence within the frame. |
| File paths in JSON | Relative to the cache folder root, forward slashes, e.g. `"frames/f0042.jpg"`. |
| Floats in JSON | Lat/lon: 6 decimals. In `map.json`: step `pod`, `canopy` and `top_cells.p` to 4 decimals, but **`prior` and `final` probabilities unrounded** (full float64; cell values are around 1e-4, so rounding would break the sum checks). Everything else: 3 decimals. |
| Missing values | `null`, never omitted, never `NaN`. |
| Version | Every top-level JSON file the pipeline writes has `"contract_version": "1.1"`. Readers also accept `"1.0"`: 1.1 only adds optional fields, which read as `null` in a 1.0 file. |

## 3. Folder layout

```
cache/
  sample/                 # fake data, committed to git in hour 1 (D)
  demo/                   # the real demo survey, generated by the pipeline, NOT committed
    manifest.json
    survey.json
    detections.json
    map.json
    metrics.json
    frames/<frame_id>.jpg       # 1000×750 JPEG, quality 85
    crops/<detection_id>.jpg    # 256×256 JPEG, quality 90
```

The website reads from `web/public/cache/<name>/`. The pipeline's last step (and `write_sample`) copies `cache/<name>/` there. `web/public/cache/sample/` is committed; `web/public/cache/demo/` is not. The folder name is chosen by the env var `VITE_CACHE_DIR` (default `sample`).

Data that must **never** be in the cache (it would leak the answers to the website): ground-truth person boxes, which frames contain people, anything under `data/`.

## 4. The demo survey, in one paragraph

The demo survey is **500 frames** cut from HERIDAL **test** images (never used in training). Each frame is a **1000 × 750 px** crop of an original 4000 × 3000 photo (a few originals are 4000 × 2250). Roughly **6** frames contain people; the rest are empty. Each frame stands for one drone photo. The frames are laid on a **simulated lawnmower flight path over Mount Seymour**: real photos, simulated positions. Every frame uses a ground sample distance of **0.02 m/px**, so its footprint is **20 m × 15 m**. The website and the pitch must say "simulated flight path" wherever positions are shown.

## 6. `survey.json`

One entry per frame. **Writers:** D (frame list, flight order, ranking) using B's functions (pose, footprint).

```json
{
  "contract_version": "1.1",
  "survey_id": "seymour-demo",
  "simulated_path": true,
  "area": {
    "name": "Mount Seymour, North Vancouver (simulated flight path)",
    "lkp": {"lat": 49.370000, "lon": -122.945000}
  },
  "frames": [
    {
      "id": "f0017",
      "file": "frames/f0017.jpg",
      "width_px": 1000,
      "height_px": 750,
      "flight_index": 16,
      "source": {"image": "test_SB_0007.jpg", "x0": 1000, "y0": 1500},
      "pose": {
        "lat": 49.369812,
        "lon": -122.946130,
        "alt_agl_m": null,
        "heading_deg": 90.0,
        "gsd_m": 0.02
      },
      "footprint": [[-122.946027, 49.369902], [-122.946027, 49.369722],
                    [-122.946233, 49.369722], [-122.946233, 49.369902]],
      "score": 0.874,
      "rank": 3,
      "n_candidates": 1
    }
  ]
}
```

| Field | Type | Written by | Notes |
|---|---|---|---|
| `area.lkp` | LatLon | D (value chosen by B) | Last known point of the missing person. Centre of the search grid. |
| `frames[].id` | string | D | `f` + 4 digits, numbered by `flight_index + 1`. |
| `frames[].flight_index` | int | D | 0-based order the drone took the photo. |
| `frames[].source` | object | D | Original HERIDAL image and the top-left pixel of the frame inside it. For debugging and attribution only. |
| `frames[].pose.lat/lon` | float | B | Ground point under the **centre** of the frame. |
| `frames[].pose.alt_agl_m` | float \| null | B | Height above ground. `null` on the simulated path (GSD is given directly). |
| `frames[].pose.heading_deg` | float | B | See §2. On the simulated path, 90 or 270. |
| `frames[].pose.gsd_m` | float | B | Metres per pixel. 0.02 on the simulated path. |
| `frames[].footprint` | `[[lon, lat] × 4]` | B | Image corners in order: **top-left, top-right, bottom-right, bottom-left** (image orientation, not compass). Not closed (4 points, first ≠ last). In the example, heading 90° means the image top faces east, so the image's top-left corner is the footprint's north-east corner. |
| `frames[].score` | float | D | Max detection confidence in the frame, `0.0` if none. |
| `frames[].rank` | int | D | 1 = most likely to contain a person. Unique, 1…N. |
| `frames[].n_candidates` | int | D | Number of detections with `conf ≥ candidate_threshold` (see §7). |

Frames are listed in **flight order** (ascending `flight_index`).

## 7. `detections.json`

All detections for all frames, in one file. **Writers:** D, using A's detector output and B's pixel-to-GPS function.

```json
{
  "contract_version": "1.1",
  "model": "yolo11s-heridal-tiled-hn",
  "save_threshold": 0.05,
  "candidate_threshold": 0.25,
  "frames": {
    "f0017": [
      {
        "id": "f0017-d01",
        "box_px": [512, 300, 560, 362],
        "conf": 0.874,
        "crop": "crops/f0017-d01.jpg",
        "lat": 49.369806,
        "lon": -122.946118,
        "radius_m": 10.0
      },
      {
        "id": "f0017-d02",
        "box_px": [88, 610, 120, 641],
        "conf": 0.091,
        "crop": null,
        "lat": 49.369883,
        "lon": -122.946199,
        "radius_m": 10.0
      }
    ],
    "f0018": []
  }
}
```

| Field | Type | Written by | Notes |
|---|---|---|---|
| `model` | string | A | Name of the weights used. |
| `save_threshold` | float | A | Lowest confidence kept. Low on purpose, so ranking can use weak signals. |
| `candidate_threshold` | float | A | Confidence at which a detection becomes a review-queue item. Chosen by A on the validation set. |
| `frames` | object | D | **Every frame id appears**, with `[]` when nothing was detected. |
| `box_px` | `[x1,y1,x2,y2]` int | A | In the frame's own pixel coordinates (1000 × 750). |
| `conf` | float | A | Detector confidence. |
| `crop` | string \| null | A (file) / D (path) | 256 × 256 JPEG: a 128 × 128 px window centred on the box, upscaled 2×. **Only for `conf ≥ candidate_threshold`; `null` below it.** |
| `lat`, `lon` | float | B | Ground position of the box centre. |
| `radius_m` | float | B | Position uncertainty. **10.0 on the simulated path** (stated assumption). The map draws the pin as a circle of this radius. |

Detections within a frame are sorted by descending `conf`.

## 8. `map.json`

The search grid. **Writer:** D, using C's functions. The website replays the steps in the browser with C's TypeScript mirror of the update.

```json
{
  "contract_version": "1.1",
  "grid": {
    "origin_nw": {"lat": 49.374492, "lon": -122.951898},
    "cell_m": 20,
    "rows": 50,
    "cols": 50
  },
  "lkp": {"lat": 49.370000, "lon": -122.945000},
  "params": {
    "recall": 0.80,
    "recall_source": "metrics.detector.recall",
    "pod_cap": 0.95,
    "review_pod": 0.90,
    "prior_source": "placeholder"
  },
  "prior": {"p": [0.0004, "... 2500 values ..."], "outside": 0.35},
  "canopy": [null, 0.62, "... 2500 values, null where no frame covers the cell ..."],
  "steps": [
    {"frame_id": "f0001", "cells": [[1234, 0.2104], [1235, 0.0871]]}
  ],
  "final": {"p": ["... 2500 values ..."], "outside": 0.41},
  "top_cells": [
    {"idx": 1288, "lat": 49.369911, "lon": -122.941275, "p": 0.0213, "canopy": 0.81}
  ]
}
```

### Grid conventions (get these exactly right)

- The grid is **1,000 m × 1,000 m**, centred on the LKP, **20 m** cells, **50 × 50 = 2,500 cells**.
- `origin_nw` is the **north-west corner** of the grid.
- **Row 0 is the northernmost row. Column 0 is the westernmost column.**
- Flat index: `idx = row * cols + col`. All `p` and `canopy` arrays are row-major, length `rows * cols`.
- Cell centre:
  - `lat = origin_nw.lat − (row + 0.5) · cell_m / 111320`
  - `lon = origin_nw.lon + (col + 0.5) · cell_m / (111320 · cos(origin_nw.lat in radians))`
- The cell polygon is the square between the edges at `row`, `row+1`, `col`, `col+1` using the same formulas.

### Field meanings

| Field | Type | Notes |
|---|---|---|
| `params.recall` | float | Detector recall used in POD. Copied from `metrics.detector.recall` once A has it; placeholder 0.80 before that. |
| `params.pod_cap` | float | No single look can take a cell's POD above this. |
| `params.review_pod` | float | POD applied when a searcher marks a crop "not a person" (see `LANE_C_SEARCH.md`). |
| `params.prior_source` | string \| null | **1.1.** `"placeholder"` when the pipeline used the placeholder prior; otherwise the citation of the lost-person statistics the prior came from (written by lane C). `null` in 1.0 files. The website shows a "Placeholder prior" badge when it is `"placeholder"`. |
| `prior.p` | float[2500] | Probability the person is in each cell before any photo. |
| `prior.outside` | float | Probability the person is outside the grid. **`sum(prior.p) + prior.outside = 1`** (within 1e-6). |
| `canopy` | (float \| null)[2500] | Estimated canopy fraction 0–1 per cell, averaged over the frames that covered it. `null` if no frame covered it. |
| `steps` | list | One entry per frame, **in flight order**. `cells` = `[idx, pod]` pairs for every cell this frame covered, `pod` already includes overlap and the cap. Cells with `pod < 0.001` are omitted. |
| `final` | object | The result of applying every step, **with the pods exactly as written (4 decimals)**, to the unrounded prior. Written unrounded. The website must reproduce it by replaying `steps` (the TS mirror's test). |
| `top_cells` | list | Top 5 cells by `final.p`, descending. |

The update applied per step (C implements it in Python and TypeScript):

```
denominator = 1 − Σ_cells_in_step  p[idx] · pod
p[idx] ← p[idx] · (1 − pod) / denominator     for cells in the step
p[j]   ← p[j] / denominator                   for all other cells
outside ← outside / denominator
```

## 9. `metrics.json`

Everything the metrics screen and the pitch quote. **Writers:** D, from A's, C's and D's own evaluation functions.

```json
{
  "contract_version": "1.1",
  "detector": {
    "model": "yolo11s-heridal-tiled-hn",
    "test_images": 101,
    "tiled": true,
    "threshold": 0.25,
    "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0},
    "sar": {"precision": 0.0, "recall": 0.0, "ap": 0.0},
    "recall": 0.0,
    "seconds_per_image": 0.0
  },
  "baseline_human": {
    "precision": 0.59,
    "recall": 0.68,
    "seconds_per_image": 33,
    "source": "Pyrrö, Naseri & Jung 2021, arXiv:2111.09406"
  },
  "ablations": [
    {"name": "Stock model, no tiling",                     "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}},
    {"name": "Fine-tuned on tiles, run on shrunk photos",  "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}},
    {"name": "Stock model, full-resolution photo",         "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}},
    {"name": "Fine-tuned on tiles, full-resolution photo", "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}},
    {"name": "Trained and run on whole photos",            "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}},
    {"name": "Fine-tuned + tiling",                        "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}},
    {"name": "+ hard negatives",                           "voc": {"precision": 0.0, "recall": 0.0, "ap50": 0.0}}
  ],
  "ranking": {
    "n_frames": 500,
    "n_positive": 6,
    "flight_order": {"frames_to_first_hit": 0, "frames_to_all_hits": 0},
    "ranked":       {"frames_to_first_hit": 0, "frames_to_all_hits": 0},
    "expected_first_hit_random_order": 71.6,
    "minutes_at_human_pace": {"flight_order_first": 0.0, "ranked_first": 0.0},
    "note": "Minutes use the published 33 s per image, measured on full 4000×3000 photos."
  },
  "search_sim": {
    "simulated": true,
    "trials": 1000,
    "seed": 7,
    "found_by_drone_rate": 0.0,
    "methods": [
      {"name": "Prior only",                  "median_cells": 0, "p90_cells": 0},
      {"name": "Naive: photographed = cleared", "median_cells": 0, "p90_cells": 0},
      {"name": "Sightline: canopy-aware",      "median_cells": 0, "p90_cells": 0}
    ],
    "in_survey": null
  }
}
```

| Block | Owner (computes) | Notes |
|---|---|---|
| `detector` | A | On the full HERIDAL test set (101 images), tiled inference. `threshold` = `candidate_threshold` (chosen on the **validation** set by maximising F2). `recall` is a copy of `voc.recall` and is what C uses. `sar` uses the loose SAR-APD matching from the AIR paper. A writes this block plus `ablations` to `data/work/detect/detector_metrics.json` on the desktop; the pipeline reads it. |
| `baseline_human` | fixed | Do not change these numbers; they're published. |
| `ablations` | A | Same test set, same scoring, one row per variant. Names exactly as shown, in this order (`sightline/ml/evaluate.py` `ABLATION_NAMES`); a variant not measured is omitted, never written as zeros. The first two shrink the whole photo to 1024 px, the next two run the whole photo at full resolution (imgsz 4000) in one pass, "Trained and run on whole photos" trains and runs at 1920 px, and "Fine-tuned + tiling" is the reported detector. **Renamed 2026-10-18 (signed off by Dan, lane A):** "Fine-tuned, no tiling" is now "Fine-tuned on tiles, run on shrunk photos" and three rows were added; files written before then still carry the old name and four rows, and the web app maps the old name to the new one. |
| `ranking` | D | `frames_to_first_hit` = 1-based position of the first frame that truly contains a person, when frames are reviewed in that order. `expected_first_hit_random_order` = (N + 1) / (k + 1) for N frames and k positives: what flight order gives on average, so one lucky or unlucky shuffle can't mislead. |
| `search_sim` | C | `median_cells` / `p90_cells` = how many cells a ground team checks, in descending probability order, before reaching the true cell, over trials where the drone did **not** find the person. Lower is better. `found_by_drone_rate` = share of trials where the survey itself found the person. **1.1:** `in_survey` is `null` or `{"trials": int, "methods": [same names, same order as methods]}`: the same statistics computed only over the not-found trials whose true cell was photographed by the survey (lane C's `simulate` fills it). In `in_survey` the true cell is ranked **only among photographed cells** (overlap > 0), the same rule as the Search next panel, so its values are "cells checked inside the surveyed area" and can never exceed the number of photographed cells. |

All zeros above are placeholders; the sample cache uses plausible fake numbers, clearly marked `"model": "SAMPLE"`.

## 10. Changing the contract

1. Propose the change in the team channel: which field, why, which lanes it touches.
2. Everyone affected agrees.
3. D updates this file, bumps `contract_version` (1.0 → 1.1), updates `sightline/contract.py`, regenerates `web/src/contract.ts` and the sample cache, all in **one commit**.
4. Nobody else edits `sightline/contract.py`.

### Changelog

- **1.1** (additive, agreed by lanes C and D): `map.json` `params.prior_source: string | null`; `metrics.json` `search_sim.in_survey: {trials, methods} | null`. Writers stamp `"1.1"`; readers accept `"1.0"` and `"1.1"`.

**Frozen at hour 3.** After that, only additive changes (new optional fields) unless the whole team agrees.

## 11. Validation checklist (D runs this on every pipeline run)

- [ ] Every file parses with the Pydantic models in `sightline/contract.py`.
- [ ] `survey.frames` has exactly `n_frames` entries, ids unique, `flight_index` 0…N−1 with no gaps.
- [ ] `rank` values are exactly 1…N.
- [ ] Every frame id in `survey.json` is a key in `detections.frames`, and vice versa.
- [ ] Every `file` path and every non-null `crop` path exists on disk; `crop` is non-null exactly when `conf ≥ candidate_threshold`.
- [ ] Every footprint has 4 corners, all inside or overlapping the grid.
- [ ] `sum(prior.p) + prior.outside` and `sum(final.p) + final.outside` are within 1e-6 of 1.
- [ ] `len(steps) == n_frames` and the steps are in flight order.
- [ ] Replaying `steps` (pods as written) on `prior` in Python reproduces `final` within 1e-9.
- [ ] No ground-truth data anywhere in the cache.
